# Генплан 3D — ТС Оскемен

Цифровой двойник нефтебазы: 3D-генплан по листам 5632.29-ГП-001…005, технологические операции и модель перекачки
(АК-004/041/045), надземные и подземные сети, ПАЗ, виртуальный обход, сверка с чертежами, кинорежим.
Three.js r160. На выходе — **один автономный HTML-файл**, работающий без интернета (в т. ч. на телефоне).

## Требования заказчика

Постоянные инструкции, контекст проекта, роль эксперта и мастер-промт кинорежима — `docs/brief/` (обязательны для всей
разработки). Анализ соответствия проекта этим требованиям и рекомендуемый порядок работ — `docs/analysis/`.

## Сборка и разработка

Нужен Node.js ≥ 20.19. Один раз установить зависимости (Vite и плагин склейки в один файл):

```bash
npm install
```

Режим разработки: сервер на http://localhost:5173. Любая правка в `src/`, `data/`, `assets/`, `vendor/` сама перезагружает страницу.

```bash
npm run dev
```

Сервер открыт и в локальной сети, поэтому с телефона в той же Wi-Fi можно открыть `http://<ip-компьютера>:5173`.
Ошибки в консоли браузера указывают на настоящий файл и строку раздела (например, `40-pnet.js:1396`).

Рабочая сборка через Vite: один автономный минифицированный файл `dist/genplan-3d-oskemen.html` (≈10,6 МБ, исходник был 12,4 МБ).

```bash
npm run build
```

Эталонная сборка без минификации: `dist/reference/genplan-3d-oskemen.html`. Её sha256 хранится в `tools/reference.sha256`
(до шага 3 совпадал с исходным файлом v0.42; обновляется после каждой проверенной правки).

```bash
npm run build:ref
```

Полная проверка: сверка эталонной сборки с `tools/reference.sha256`, обе сборки и их сравнение в headless Chromium
(загрузка без ошибок JS, все панели, статистика отрисовки и видимые тексты интерфейса должны совпасть).

```bash
npm test
```

Отпечаток состояния после загрузки — главный инструмент проверки рефакторинга (`tools/fingerprint.mjs`):
каждый объект сцены (геометрия, мировая матрица, материал, видимость), данные после инициализации (`NETS`, `PH`, `UG_DATA`,
`PHX_DATA`, `PROC`, `PIPEREG`, `OBJ` …, включая свойства на массивах и разделяемые ссылки) и журналы модулей F24–F34.

```bash
node tools/fingerprint.mjs dist/reference/genplan-3d-oskemen.html до
```

```bash
node tools/fingerprint.mjs --diff dist/fp/до.json dist/fp/после.json
```

Переменные: `FP_WAIT` — когда снимать (мс от начала загрузки, по умолчанию 16000), `FP_SEED` — зерно `Math.random`
(генератор mulberry32), `FP_THROTTLE` — замедлить процессор
(например, 3), чтобы проверить зависимость от скорости машины. Доступ к сцене для автотестов включается только адресом `?debug`.

Для смоук-теста нужен пакет `playwright`: `npm i --no-save playwright && npx playwright install chromium`.

GitHub Actions (`.github/workflows/build.yml`) на каждый push делает то же самое и выкладывает `genplan-3d-oskemen.html`
и скриншоты смоук-теста как артефакт сборки (вкладка Actions → запуск → Artifacts).

### Две сборки: зачем

- **Vite** (`npm run build`) — то, что отдаётся пользователям: минифицированный JS и CSS, Three.js без обёртки data:URL.
- **Эталонная** (`npm run build:ref`, `tools/build.mjs`) — склейка без преобразований. Пока идёт рефакторинг без изменения
  поведения, она обязана совпадать с эталоном побайтно (`npm run verify`), а Vite-сборка — вести себя так же, как она (`npm test`).

### Разделы кода (`src/app`)

Все разделы выполняются в **общей области видимости одного модуля**: это не ES-модули, а части одного скрипта.
Порядок важен, переименовывать с изменением номера можно только с учётом зависимостей.

- 01–07 — сцена, свет и качество (`VIS`), материалы и примитивы (`MATX`), рельеф (`RELIEF17`), окружение (`ENV`), ж/д и эстакада 177, фасады (`FAC`)
- 08–12 — модели «Цифрового склада» (`DX3`), вагоны (`TCAR`), пожаротушение и др. (`F24`, `F25`, `F27`)
- 13 — реестр объектов генплана `OBJ`
- 14–18 — сети и заплатки сверки (`F28`, `F34`, `F32`, `F29`, `F31`)
- 19–23 — реестр труб, подземные сети (`PIPED`, `UGN`), освещение, загрузка 3D-моделей
- 24–30 — РВС (`RVSD`), РГС (`RGSD`), документы (`DXD`), эстакада (`ESTQ`), граф ТП `PROC`
- 31–39 — логика и интерфейс «Технологии», насосный цех (`PHX`), модель перекачки, звук, выбор, камера, панели
- 40–49 — трубопроводная сеть (`PNET`), поток (`PFLOW`), ПАЗ (`EMG`), обход (`WALK`), генплан (`GEO`), РГС (`RGSP`), документы (`DXP`), гидравлика (`HYD35`, `HYDX`), подсветка подземки (`UGHL`)
- 50 — кинорежим (`CINE`), 51 — главный цикл

### Маркеры сборки

| Маркер | Где | Что подставляется |
|---|---|---|
| `<!--@inline путь-->` | HTML | текст файла |
| `<!--@base64 путь-->` | HTML | файл в base64 |
| `<!--@concat каталог-->` | HTML | все `*.js` каталога по порядку имён |
| `'/*@base64 путь*/'` | JS-строка | файл в base64 |
| `/*@inline путь*/null` | JS | JSON как есть |
| `/*@json путь*/null` | JS | JSON-файл, сжатый в одну строку |

JSON в `data/` хранится отформатированным (`npm run fmt:data`, проверка — `node tools/fmt-data.mjs --check`) и при сборке
сжимается в одну строку (маркер `@json`).

### Производительность (v0.45)

Профиль — `npm run profile [имя]` (`tools/profile.mjs`): время каждого раздела при запуске, первый кадр, куча,
вызовы отрисовки за кадр (в среднем по 40 кадрам), вклад групп сцены. Программный рендер headless Chromium медленнее
реального GPU — важны доли и сравнение «до/после».

| | v0.44 | v0.45 |
|---|---|---|
| вызовов отрисовки за кадр, камера неподвижна (в среднем) | 1886 | 1235 |
| то же при движении камеры | 1886 | 1760 |
| основной проход (без теней) | 1178 | 1060 |

- Тень пересчитывается по требованию (`VIS`): при движении камеры или солнца — каждый кадр, иначе раз в 4 кадра
  (подвижные механизмы); кинорежим и обход — каждый кадр. Проход теней — около 700 вызовов.
- Ограждение 427, стенка обвалования 431 и стена 799 — один меш на материал вместо 135 отрезков (`mergeStatic`).
- Подписи пишутся в DOM только при изменении.
- Проверено: отпечаток (меняются только объединённые меши), скриншоты пяти видов до/после — отличия субпиксельные
  (растр сварной сетки ограждения).
- Не делалось, потому что замер не показал выигрыша: ленивая загрузка редких режимов (инициализация каждого < 15 мс),
  разбор `purgeOld` (постройка удаляемого < 15 мс; основное время `40-pnet` — новая геометрия труб).
  Покадровый JavaScript — меньше 1 % времени кадра, всё остальное — сама отрисовка.

### Мобильный интерфейс (v0.46)

| Телефон (iPhone 13) | v0.45 | v0.46 |
|---|---|---|
| верхняя панель, доля экрана: портрет / альбом | 25 % / 27 % | 6 % / 11 % |
| пересечений подписей: портрет / альбом | 65 / 85 | 0 / 0 |

- Компактный режим — узкий **или** низкий экран (`max-width: 700px`, `max-height: 500px`), т. е. и телефон в альбомной
  ориентации (раньше в альбомной показывалась полная сноска на 2/3 экрана). Заголовок — одна строка, кнопки режимов —
  в меню «☰» (сетка 3×4, крупные кнопки); выбор пункта закрывает меню до открытия панели. Счётчик производительности
  в компактном режиме скрыт. На компьютере панель прежняя.
- Подписи без наложений (на всех экранах, `lblFlush` в `13-obj-registry.js`): при пересечении остаётся более важная
  (тревога, пожар → уровни → номера объектов → арматура), при равной — ближняя к камере; скрытая появляется, когда место
  освобождается (при повороте или приближении камеры).

### Обучение при виртуальном обходе (v0.50)

Модуль `src/app/43b-trn.js`, банк заданий `data/trn-tasks.json`, кнопка «Обучение». Все задания проверяются по состоянию модели.
- **Маршрут осмотра.** 7 контрольных точек (РВС, РГС, эстакада 177, Н-5/Н-6, станция 186, вышки 800, НС 644). Точка засчитывается,
  когда объект удерживается в прицеле обхода 1,5 с (дальность прицела 14 м). Порядок любой; переход «К точке» отмечается в протоколе.
- **Контрольные вопросы** (8). Ответы взяты из строк паспортов реестра со статусом «подтверждено», после ответа показывается источник.
  Засчитывается ответ с первой попытки. Банк учебный: до применения в обучении персонала его утверждает ответственный за обучение.
- **Поиск неисправности.** В модель ПАЗ скрыто вводится отказ неработающего насоса цеха 200 (защита двигателя, пуск блокируется)
  или заклинивание арматуры с электроприводом, доступной прицелу обхода. Обучаемый находит её по карточке объекта и журналу,
  наводит прицел и нажимает «Доложить». Ошибочные доклады и время учитываются; по завершении неисправность снимается.
- **Протокол.** Маршрут, ответы с источниками, поиск неисправности, журнал; выгрузка в .txt. Хранится только в открытом окне.
- Не входит: тесты без обхода, роли и учёт обучаемых, сохранение результатов между сеансами, сценарии действий персонала при аварии.
