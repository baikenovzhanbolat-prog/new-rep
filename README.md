# Генплан 3D — ТС Оскемен

Цифровой двойник нефтебазы: 3D-генплан по листам 5632.29-ГП-001…005, технологические операции и модель перекачки
(АК-004/041/045), надземные и подземные сети, ПАЗ, виртуальный обход, сверка с чертежами, кинорежим.
Three.js r160. На выходе — **один автономный HTML-файл**, работающий без интернета (в т. ч. на телефоне).

## Сборка

Нужен Node.js ≥ 18, сторонних зависимостей для сборки нет.

```bash
node tools/build.mjs
```

Результат: `dist/genplan-3d-oskemen.html`. Его можно открыть в браузере.

```bash
node tools/verify.mjs
```

Сверяет сборку с эталоном `tools/reference.sha256`. Сейчас эталон — исходный файл v0.42: сборка совпадает с ним побайтно.

```bash
node tools/smoke.mjs
```

Смоук-тест в headless Chromium: загрузка, отрисовка и открытие панелей без ошибок JS (нужен пакет `playwright`).

GitHub Actions (`.github/workflows/build.yml`) на каждый push собирает файл, сверяет его, прогоняет смоук-тест
и выкладывает `genplan-3d-oskemen.html` как артефакт сборки (вкладка Actions → запуск → Artifacts).

## Структура

| Путь | Что лежит |
|---|---|
| `src/index.html` | разметка-оболочка с маркерами сборки |
| `src/styles.css` | стили интерфейса |
| `src/app/NN-*.js` | код приложения по разделам; при сборке склеиваются **по порядку имён** в один `<script type="module">` |
| `data/*.json` | крупные данные из кода: сети ГП-005 (`NETS`, `GP5V`, `UG_DATA`), граф ТП (`PROC`), рельеф, насосный цех и т. д. |
| `assets/scans/*.webp` | сканы листов чертежей (просмотр документов) |
| `assets/docs/` | «Резервуар 1.pdf» и его страницы |
| `assets/bin/` | двоичные данные: 3D-модели склада и вагона (zlib), рельеф, текстура |
| `vendor/` | three.module.js r160, OrbitControls.js, mp4-muxer 5.2.2 (MIT) |
| `tools/` | `build.mjs`, `verify.mjs`, `smoke.mjs`, `split.mjs` (одноразовое разбиение исходного HTML) |

### Разделы кода (`src/app`)

Все разделы выполняются в **общей области видимости одного модуля**: это не ES-модули, а части одного скрипта.
Порядок важен, переименовывать с изменением номера можно только с учётом зависимостей.

- 01–07 — сцена, свет и качество (`VIS`), материалы и примитивы (`MATX`), рельеф (`RELIEF17`), окружение (`ENV`), ж/д и эстакада 177, фасады (`FAC`)
- 08–12 — модели «Цифрового склада» (`DX3`), вагоны (`TCAR`), пожаротушение и др. (`F24`, `F25`, `F27`)
- 13 — реестр объектов генплана `OBJ`
- 14–18 — сети и заплатки сверки (`F28`, `F34`, `F32`, `F29`, `F31`)
- 19–23 — реестр труб, подземные сети (`PIPED`, `UGN`), освещение, загрузка 3D-моделей
- 24–30 — РВС (`RVSD`), РГС (`RGSD`), документы (`DXD`), эстакада (`ESTQ`), граф ТП `PROC`
- 31–39 — логика и интерфейс «Технологии», насосный цех (`PHX`), модель перекачки, звук, выбор, камера, панели
- 40–49 — трубопроводная сеть (`PNET`), поток (`PFLOW`), ПАЗ (`EMG`), обход (`WALK`), генплан (`GEO`), РГС (`RGSP`), документы (`DXP`), гидравлика (`HYD35`, `HYDX`), подсветка подземки (`UGHL`)
- 50 — кинорежим (`CINE`), 51 — главный цикл

### Маркеры сборки

| Маркер | Где | Что подставляется |
|---|---|---|
| `<!--@inline путь-->` | HTML | текст файла |
| `<!--@base64 путь-->` | HTML | файл в base64 |
| `<!--@concat каталог-->` | HTML | все `*.js` каталога по порядку имён |
| `'/*@base64 путь*/'` | JS-строка | файл в base64 |
| `/*@inline путь*/null` | JS | JSON как есть |
| `/*@json путь*/null` | JS | JSON-файл, сжатый в одну строку |

Большинство JSON в `data/` пока лежит одной строкой (как в исходнике), чтобы сохранить побайтовое совпадение.
Форматирование данных — следующий шаг, после него эталон обновляется (`node tools/verify.mjs --update`).
