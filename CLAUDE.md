# CLAUDE.md

Цифровой двойник нефтебазы ТС Оскемен (Three.js r160). Результат — один автономный офлайн-HTML.
Пользователь пишет по-русски; отвечать по-русски. Тексты интерфейса и комментарии в коде — на русском.

## Команды
- `npm install` — один раз (Vite, vite-plugin-singlefile)
- `npm run dev` — сервер разработки с автоперезагрузкой (порт 5173)
- `npm run build` — рабочая сборка Vite → `dist/genplan-3d-oskemen.html` (минифицирована)
- `npm run build:ref` — эталонная сборка без преобразований → `dist/reference/genplan-3d-oskemen.html`
- `npm run verify` — sha256 эталонной сборки против `tools/reference.sha256`
- `npm test` — verify + обе сборки + смоук-тест с их сравнением в Chromium (playwright уже установлен в облачном окружении)
- `node tools/verify.mjs --update` — обновить эталон после проверенной правки
- `node tools/fingerprint.mjs <файл.html> <имя>` и `--diff A.json B.json` — отпечаток сцены и данных (главная проверка рефакторинга)
- `npm run fmt:data` — форматирование data/*.json

## Правила
- Править только исходники (`src/`, `data/`, `assets/`, `vendor/`), не `dist/`.
- Vite получает код приложения как один виртуальный модуль `/@genplan/app.js` (см. `tools/vite-plugin-genplan.mjs`);
  `three` и OrbitControls берутся из `vendor/`, importmap в Vite-сборке удаляется. npm-пакет three не используется.
- Маркеры данных в `src/app` не должны менять число строк раздела (на этом держится карта исходников в dev).
- `src/app/NN-*.js` — части **одного** `<script type="module">` с общей областью видимости, склеиваются по порядку имён.
  Не превращать их в ES-модули без отдельной задачи; порядок важен (модули ссылаются на объявленное выше).
- Рефакторинг без изменения поведения: до правки снять отпечаток эталонной сборки, после — снять снова и сравнить (`--diff`);
  должно совпасть всё, кроме намеренно изменённого. Затем `npm test`, `node tools/verify.mjs --update`.
  Отпечаток зависит от времени (см. «Известные проблемы» в README): сравнивать сборки, снятые в одинаковых условиях.
- Если правка меняет поведение: прогнать `smoke`, проверить вручную, поднять версию в `<title>` и подвале (`src/index.html`) и в package.json.
- Правок данных «по месту» (по координатам с допуском, по индексам) в код не добавлять — менять `data/*.json`.
- `PH.pipes`: последний элемент-объект записи трубы — её теги (раскладываются в свойства массива при загрузке).
- Маркеры сборки описаны в README.md; в исходниках не должно появляться строк `@inline`/`@base64`/`@json`/`@concat` вне маркеров.
- Многие параметры модели условные (помечены «условно» в коде): не выдавать их за данные чертежей.
